# Creator onboarding: free art workflows

## Recommended starting point

Use the native Creator Foundry for site-owned assets and publishing workflows. External editors below are separate applications, not installed Knightfall services.

| Tool | Best use | Chromebook | Export |
|---|---|---|---|
| [Piskel](https://www.piskelapp.com/) | First pixel sprites and frame animation | Browser, no installation | PNG sprite sheet, GIF |
| [Pixelorama](https://orama-interactive.itch.io/pixelorama) | Larger pixel-art projects, layers and animation | Browser build where supported; Linux build via Crostini if compatible | PNG, sprite sheet |
| [Blender](https://www.blender.org/) | 3D modeling, rigging and rendering | Linux installation on compatible hardware; not a browser editor | GLB/glTF, PNG |

## First exercise

1. Start with a 32×32 or 64×64 transparent sprite in Piskel.
2. Make four idle frames with a consistent canvas and pivot; preview at 6–8 fps.
3. Export a PNG sheet and a GIF preview; keep the editable source separately.
4. In Creator Foundry, use the available sprite/image tools to inspect dimensions and preview the asset before submitting it. Do not assume an external editor is embedded or that upload automatically publishes.
5. Record author, source, license, dimensions, frame count and intended game. Use original artwork or explicitly licensed material.

## When to move up

Choose Pixelorama when layer management and longer animations become limiting. Choose Blender only for actual 3D requirements; begin with a low-poly model and export GLB plus a PNG thumbnail. Test the model on a supported device before integrating it. Avoid paid add-ons and cloud rendering by default.

This is a workflow evaluation, not a claim of device-specific installation or integration testing. Piskel is the recommended first tool for browser-first onboarding.
