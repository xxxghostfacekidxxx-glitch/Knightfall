Important: inspiration is not installation

Ash-Fall currently uses Cloudflare Pages for the website and a Cloudflare Worker for the API, with D1, KV, and R2. Full self-hosted apps that expect Docker, PHP, Ruby, a long-running Node server, or their own database cannot run directly inside a Worker. This page is a curated launchpad, not a claim that these six separate applications have been installed. We can reuse compatible ideas and connect external services only after their hosting, security, cost, and maintenance are settled.

ELSocial-network reference

Elgg

A mature social-network framework with user profiles, activity streams, groups, relationships, and a plugin ecosystem.

Best forSocial feature architecture

Ash-Fall fit: use it as a feature reference for profile feeds, groups, and extensibility. Knightfall already has native profiles and friends; replacing the current app with Elgg would be a separate migration, not a drop-in addition.

FLForum UX reference

Flarum

A modern discussion forum focused on readable threads, tags, extensions, and a clean interface.

Best forDiscussion and forum UX

Ash-Fall fit: borrow interaction patterns for thread lists, topic labels, replies, and moderation clarity. The Madhouse already has its own API and database, so installing Flarum alongside it would split the community unless deliberately integrated.

Official site ↗Source repository
IMSeparate media service

Immich

A self-hosted photo and video management application with a polished library-oriented experience.

Best forLarge personal media libraries

Ash-Fall fit: study its media-library workflows. It is not a Cloudflare Worker package. Knightfall already has a private R2-backed vault; Immich would require separate compatible hosting and a carefully designed authentication boundary before any account integration.

Official site ↗Source repository
UMAnalytics service

Umami

A privacy-focused website analytics platform with traffic and event reporting.

Best forSite usage insights

Ash-Fall fit: a candidate for measuring page usage without building every report ourselves. It is not configured on this site today. Before adding its tracking script, decide hosting, privacy notice, retention, and which events are appropriate to collect.

SENSIBLE IMPLEMENTATION ORDER

What we should actually do next.

  1. Keep the native community unified. Improve profiles, friends, messages, and the Madhouse inside Knightfall rather than splitting members across separate platforms.
  2. Harden and expand the private vault. Confirm R2 limits, ownership checks, upload validation, and recovery before adding a second media service.
  3. Add privacy-conscious analytics deliberately. Evaluate Umami hosting and consent/privacy requirements before loading any tracker.
  4. Expand Chaos Cartridge safely. Link to upstream playable games first. Bundle a game only after checking source and asset licenses, offline behavior, and save-data integration.
