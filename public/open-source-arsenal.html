Important: inspiration is not installation

Ash-Fall currently uses Cloudflare Pages for the website and a Cloudflare Worker for the API, with D1, KV, and R2. Full self-hosted apps that expect Docker, PHP, Ruby, a long-running Node server, or their own database cannot run directly inside a Worker. This page is a curated launchpad, not a claim that these six separate applications have been installed. We can reuse compatible ideas and connect external services only after their hosting, security, cost, and maintenance are settled.

Toolkit import rules

The source catalog and sync helper live in the repository's toolkit/ folder. Run node toolkit/sync.mjs from a local checkout to fetch the approved starter repositories into an ignored local vendor directory. Use node toolkit/sync.mjs --all to include larger verified references. Nothing is built, run, deployed, or copied into the live site automatically. Unverified repositories stay blocked until their upstream identity and license are checked.

Server panels and native/Java games need separate compatible hosting; they do not run directly on our Pages + Workers setup.

SENSIBLE IMPLEMENTATION ORDER

What we should actually do next.

  1. Keep the native community unified. Improve profiles, friends, messages, and the Madhouse inside Knightfall rather than splitting members across separate platforms.
  2. Harden and expand the private vault. Confirm R2 limits, ownership checks, upload validation, and recovery before adding a second media service.
  3. Add privacy-conscious analytics deliberately. Evaluate Umami hosting and consent/privacy requirements before loading any tracker.
  4. Expand Chaos Cartridge safely. Link to upstream playable games first. Bundle a game only after checking source and asset licenses, offline behavior, and save-data integration.
